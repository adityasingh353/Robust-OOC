# Research Audit: EXP005 - Unified Network

## 1. Repository URL and Relevance
- **Repository URL:** https://github.com/nbtin/fakenews-detection-demo
- **Relevance:** **B. Authors' broader thesis implementation containing the paper method.** 
- **Evidence:** The repository is primarily a Streamlit web-app demo for multiple papers. However, it explicitly cites the ICMR 2024 paper *"A Unified Network for Detecting Out-Of-Context Information Using Generative Synthetic Data"* in its `demo.py` strings. Furthermore, the `hybrid/` folder contains the Fairseq/OFA-based codebase used for the paper's experiments, including an investigative Jupyter notebook named `cheapfakes_detection_ICMR2024.ipynb`.

## 2. Relevant Files & Commits
- `hybrid/cheapfakes_detection_ICMR2024.ipynb`: The main notebook documenting the setup and inference commands for the ICMR 2024 paper.
- `hybrid/inference_batch_task1.py` & `hybrid/inference_batch_task2.py`: The exact batch inference scripts used to run the OFA model.
- `hybrid/utils/cheapfakes.py`: Contains the `data_preprocess` function which explicitly formats the COSMOS inputs for the OFA model.
- `hybrid/tasks/ofa_task.py` and `hybrid/models/ofa/`: The OFA model architecture and Fairseq task definitions.

## 3. OFA Pipeline Trace
The pipeline for OOC detection is fully present:
- **Exact OFA Model:** OFA (run via Fairseq).
- **Task:** SNLI-VE (Visual Entailment).
- **Prompt Formulation:** Found in `hybrid/utils/cheapfakes.py`. 
  - `src_item = dataset.encode_text(' can image and text1 " {} " imply text2 " {} "?'.format(caption, hypothesis))`
- **Output Labels:** `CONTEXT = {'yes': 0, 'no': 1}`. The string labels generated by the model are `yes` (Mapped to NOOC), `no` (Mapped to OOC), and `maybe` (neutral).
- **Inference Code:** Provided via `inference_batch_task1.py`.
- **Training Code:** Provided via `hybrid/train.py` and Fairseq bash scripts in `hybrid/run_scripts/vqa/`.

## 4. Synthetic Data Generation
- **Missing:** The repository **does NOT** contain the synthetic-data generation process described by the paper. 
- There are no scripts making calls to the GPT-3.5 API, no prompt templates for the LLM augmentation, and no transformation rules. 
- The generated training data (the ~40,000 synthetic samples) is also not included in the repository.

## 5. Checkpoints
- **Fine-tuned Unified Network Checkpoint:** Available! The notebook `hybrid/cheapfakes_detection_ICMR2024.ipynb` contains a Google Drive download command:
  - `!gdown 1LqV1za_VKx2asDcniINCD5D6LXPciiKb`
  - This downloads `checkpoint.gendata1_testtrain12.best_snli_score_0.9090.pt`, which is the exact fine-tuned weights for the SNLI-VE task used in the paper.
- **Pretrained OFA:** Standard OFA checkpoints are referenced for download in the `hybrid/transformers.md` and Fairseq scripts.

## 6. Reproducibility Classification
**Classification: B — Approximate reproduction possible** (with Exact Inference Reproduction)

**Explanation:** 
If the goal is to evaluate the *trained method* on the frozen 900-sample COSMOS-FIXED-v1 test set, an **Exact Reproduction** is possible because the exact fine-tuned checkpoint (`best_snli_score_0.9090.pt`), the exact prompt (`can image and text1... imply text2...`), and the exact inference script (`inference_batch_task1.py`) are fully available. 

However, from an end-to-end pipeline perspective (including training from scratch), it must be classified as an **Approximate Reproduction** because the synthetic data generation pipeline (GPT-3.5 prompts, rules, and the 40,000 synthetic samples) is completely missing from this repository.

## 7. Recommended Next Action
Since the exact fine-tuned checkpoint and prompt formatting for inference are available, I recommend proceeding to **Phase 2 (Dataset Adaptation Plan)** and **Phase 3 (Small Pilot)** using the downloaded checkpoint. We can map our `cosmos_test_900.csv` to the JSON format expected by `inference_batch_task1.py` and run direct inference without needing to recreate the synthetic data or train the model.
